# 05 — Corpora and goldens per repository class

Date 2026-09-26. Everything here was read, not run: `git log -1`, `git ls-files`, per-file sizes, source files
and the language references fetched at the URLs cited. No product, benchmark, test or build ran.

**How the counts were produced (inline, so no script needs to exist).** For each clone: `git ls-files -z`; each
tracked regular file that is not a symlink is sized with one `stat` per file; a file is assigned to an advertised
language by the extension table of `internal/provider/treesitter/lang/lang.go:79-89` (lower-cased extension, so
`.h` is C per `lang.go:104-106`). "Vendored" is a path segment `vendor`, `node_modules`, `third_party`,
`third-party`, `thirdparty`, `extern`, `external` or `deps`; "generated by path" is `zz_generated`, `.pb.go`,
`_generated.`, `.generated.`, a `generated/` segment, `.pb.cc`/`.pb.h`, `.min.js`; for Go, a file whose first
line matching `^// Code generated` exists is also counted (`grep -l -m1`). A **unit** is the nearest ancestor
directory holding a marker file (`go.mod`, `Cargo.toml`, `build.gradle[.kts]`, `__init__.py`, `tsconfig.json` /
`jsconfig.json`, `CMakeLists.txt`), or for Go packages and C/C++ directories the file's own directory; unit
quantiles are over units sorted by bytes. Every count is per file, never from a chunked total.

## (a) The pinned commit per corpus

**Recommendation.** Pin the seven commits in the pin table as the differential oracle's corpus, each a depth-1
clone, and enter them in `internal/bench/corpora.json` as `measured: false` with no counts, a `description` that
names the **repository class** each instantiates (from the class column of (d)), not only the language. The byte
counts above are a read-only `ls-files` measurement, not "produced by a run" in the manifest's sense
(`internal/bench/corpus_test.go:540-545`), and `validateEntry` rejects counts on an unmeasured entry
(`:587-589`); they become `measured: true` only when the benchmark run that owns the rows records them together
with the `fixture_hash`. The two private owner instances never enter the manifest; they are cited by class only.

**Why a shallow pin is enough.** The product reads a checkout only through `rev-parse --verify HEAD`
(`internal/vcs/git/git.go:325`), `ls-files -z -s -t` (`:390`), `status --porcelain=v2` (`:469`) and
`cat-file blob` (`:579`): the tree at one commit, never history. The key algebra is keyed by file, owner, operator,
target and byte range (ADR-0012:314-317), all functions of the tree. The oracle's rule is only that the commit be a
full 40-hex SHA (`corpus_test.go:564-573`). A depth-1 clone at the SHA reproduces every input bit.

**Strongest alternative, steel-manned.** Pin tags or release branches (for example a Kubernetes release tag): tags
are what users run, are stable to humans, and a full clone lets a later task bisect a divergence to a commit.

**Why the recommendation wins.** A tag is a moving name to the validator (`corpus_test.go:561-563`: "a differential
oracle whose other side moves is not an oracle"); the SHA is the identity. Bisection is over the *product's*
history against a fixed corpus, never over the corpus's history, so a full clone buys nothing the gates read, and
costs gigabytes on the host that also runs the benchmark (ADR-0012 §5: disk breaks first at scale).

**Trade-off accepted.** Pins are same-day or one-day-old snapshots of `main`, not released code, and the TypeScript
checkout is ten days older than the others; a later re-pin re-measures every band (ADR-0012:537-538).

**The measurement the benchmark task must take.** For each corpus: `git rev-parse HEAD` equals the pin and
`git ls-files -z -s` hashes to the manifest `fixture_hash`, before any row is written; fail on either mismatch.

## (b) The per-language unit to diff against the engine oracle

**Recommendation.** Two different units, stated per family: the **oracle unit** is the smallest unit the engine
analyses faithfully for that language; the **compared set** is the key set restricted, by the file component the
key already carries (ADR-0012:314-317), to the files the native side analysed. No new machinery is needed.

| language | oracle unit (engine run) | compared set | why |
|---|---|---|---|
| Go | the `go.mod` module | whole packages (every file of a package directory, `_test.go` files of the same package included; an external `_test` package is its own package) | the engine reads only the root module of a workspace (`10-engine-empirical.md:98-99`), and a file-only parse invents 960 spurious reaching-definition edges from the synthetic package initialiser (`raw/native-engine/05-file-locality.md:36,61`) |
| C/C++ | a component root: one directory subtree containing the sources **and** the headers they include | per file, with methods declared in `.c`/`.cc`/`.cpp`/`.cxx` files diffed as one set and methods declared in headers as a **separate signed band** | the engine has no translation-unit notion: it parses each source file, resolves an unresolved `#include` by basename anywhere under its input path with a Levenshtein tiebreak (`joern-cli/frontends/c2cpg/.../parser/HeaderFileFinder.scala:14-39`, engine tag v4.0.627), and parses each header in the language of its includers, both if both include it (`passes/AstCreationPass.scala:58-64` of that directory; `C2Cpg.scala:30-43`). The native side parses every `.h` once with the C grammar (`lang.go:79,104-106`), and llvm carries 17,897 `.h` files / 119.4 MB in a C++-majority tree — so header facts differ by a named cause (grammar choice and duplicate parse), which must not be allowed to cancel against source-file facts |
| Java | the build module (`build.gradle[.kts]` / `pom.xml` directory) | per file within the module | the file-only row for Java proves nothing: the exclusion "had no effect" (`raw/native-engine/05-file-locality.md:42`), so Java file-locality is **unmeasured** and the module run is the only faithful oracle |
| Python | the package subtree the engine ruling names (directory with `__init__.py` / `pyproject.toml`) | per file | file-only and package-only runs keep 100% of both families (`05-file-locality.md:37-38`); package units keep 100% (`10-engine-empirical.md:177-189`) |
| JS/TS | the `tsconfig`/`jsconfig`/`package.json` project | per file | file-only keeps 100% (`05-file-locality.md:39-40`), but a subdirectory unit keeps 99.7% / 99.9% (`10-engine-empirical.md:163-173`), so a split oracle adds a named "split" cause; projects are never split for the oracle |
| Rust | none for control/data dependence (see (c)); the crate for throughput only | — | the engine's `?`, labelled-jump and `if let` losses (`docs/research/20-native-engine-post-mvp.md:244-246`) would be encoded into any diff |

**Where the ADR is in tension with itself, resolved by the evidence.** ADR-0012:526-527 says Rust and Java "cannot
be a diff against the engine at all", while phase 3 gives Java a band gate for the dependence families
(ADR-0012:278). The evidence separates them: Java's control and data dependence **are** diffable (the engine emits
them for Java, and no Java CFG defect is recorded at the tag), so Java dependence takes the band gate on module
units; Java **`calls`** is authored (phase 4, ADR-0012:279, because the engine type-recovers nothing for Java).
Rust control and data dependence are authored because the engine is known wrong on them.

**Selection rule, for any repository of the class.** Enumerate the class's oracle units by marker (table above).
A unit is eligible when both bounds hold, each derived from the repository and machine in front of the harness:
1. *Lower bound from the band.* A unit qualifies when its family count × the band measured on that corpus is ≥ 1
   edge; at the ≈0.01% measured so far on one 161-file Go tree (`10-engine-empirical.md:221-233`) that is ≈10⁴
   edges. A unit below it has a band under one edge, i.e. it can only assert equality, which is itself a defect
   (`raw/native-engine/03-parity-and-oracle.md:65-68`). The count is read from the first engine run.
2. *Upper bound from the machine.* The unit's engine peak must fit the standing allocation (ADR-0010 decision 2).
   The first run of a language is admitted at the smallest eligible unit; its observed peak per source byte,
   measured on the 250 ms sampler, prices the next, larger unit — never a constant carried from another corpus.
Then take, in order: the smallest eligible unit; the next larger one whose bytes are at least twice it; the largest
unit that fits; and every eligible unit that is predominantly vendored or generated (one each), so those classes
are exercised. A unit the engine fails on (a deterministic crash, or an exit-0 graph with no file node,
`10-engine-empirical.md:120-121`) is excluded from the band and recorded as such; it is never counted as agreement.

**Instances of the rule on these pins** (sizes from the sub-tree table; engine cost from the paragraph above):
- Go: `staging/src/k8s.io/apimachinery` (module; engine 8.3 s / 3.38 GB, `10-engine-empirical.md:106`), then
  `staging/src/k8s.io/client-go` (`:108`); generated-heavy `staging/src/k8s.io/api` (`:104`); a second Go
  repository: the TypeScript checkout's `tsc` module with `tsc/internal/checker` in the compared set. Not
  `kubectl` (engine crash, `:110`) and not the root module (122 MB with `vendor/`) unless the machine's first
  observations price it inside the allocation.
- C/C++: `compiler-rt/lib/builtins` (C, self-contained), `libunwind` and `libcxxabi` (sources plus their `include/`),
  then `llvm/lib/Support` — whose headers sit in `llvm/include`, so its component root is `llvm/`, which fails the
  upper bound; it enters only with an input path covering both subtrees and a header-band reading. Whether each
  chosen root's includes all resolve inside it is **unavailable** (not checked; it needs an include scan).
- Java: `libs/core`, `libs/x-content`, then `modules/lang-painless`; generated: `x-pack/plugin/esql/compute`.
  `server` (91.5 MB, 2.06M lines) is the largest-that-fits candidate on a machine whose allocation prices it;
  spring's 1.5M LOC at 7.91 GB (`:75`) is the prior.
- Python: `homeassistant/helpers`, `homeassistant/util`, `homeassistant/components/mqtt`; the whole `homeassistant`
  package (1.55M lines) only if priced inside the allocation (the 1.05M-line prior needed 18.4 GB, `:79`).
- JS/TS: `extensions/git`, then `extensions/copilot` (vscode); the TypeScript checkout's `packages/typescript`.
  Never `src` (9,623 files / 133 MB, the same order as the 157.2 MB unit that crashed twice).
- Rust: `library/core`, `compiler/rustc_parse`, `library/alloc` — throughput and self-consistency only.

**Strongest alternative, steel-manned.** Diff per file everywhere: the dependence families are file-local by the
engine's own measurement (ADR-0012:116-121), a file unit is the smallest oracle run, it parallelises trivially and
it matches the native unit of caching exactly.

**Why the recommendation wins.** File-locality is measured for Python, TypeScript and C only on a 3-file C unit;
for Go it is false with a named cause, for Java it is unmeasured (`05-file-locality.md:42`), and for C/C++ header
resolution depends on the input path. A per-file engine run also pays JVM start per file (1.7–4.7 s,
`05-file-locality.md` cost table), which on 32,622 Java files is hours for no additional fidelity.

**Trade-off accepted.** Module-sized oracle units cost more engine memory per run and exclude the largest units on
a small host, so the band on those units is measured on another machine or not at all, and is said to be.

**The measurement the benchmark task must take.** Per selected unit and family: engine run A, engine run B, native
run; the A/B symmetric difference (the band) and the native/A difference, signed and per cause; the unit's edge
count (lower bound check) and tree-summed peak per source byte (upper bound check). Pass: every native difference
is within the band or fully attributed to a named cause; fail: any unattributed difference or any unit whose band
is under one edge.

## (c) Golden corpora for Rust and Java, authored from the language references

**Recommendation.** Author both in the existing golden format and procedure. The format is
`goldenCase{name, protects, mutation, src, fn, cd, du, unresolved}`
(`internal/provider/treesitter/worker/lower_fixture_test.go:15-25`); a node renders as `ENTRY`, `EXIT` or
`<text, whitespace collapsed>@<start byte>` and the sorted lists must be equal (`:27-31,101-111`); the derivation
rules sit in the table's header comment (`lower_go_test.go:10-18`, `lower_javascript_test.go:5-14`), and each case's
comment lists nodes with offsets, successors and immediate post-dominators (e.g. `lower_go_test.go:61-77`). Two
extensions are needed because the format covers only control dependence, def-use and unresolved jumps: a `rw`

**Authoring and review procedure that makes 100% equality a valid gate.** (1) Every case names its reference anchor
in `protects`, and its `mutation` names the lowering change that would fail it, as the existing tables do. (2) The
author derives nodes, successors, post-dominators and pairs by hand in the case comment from the header's rules; a
second author derives the same case independently from the source and the reference alone, and the case lands only
when both derivations agree. (3) No case is derived from, or corrected against, engine output or native output: a
failing case is resolved by re-reading the reference, never by accepting the producer's answer. (4) The case list
covers every construct kind the language's lowering dispatches on; a lowering kind with no case is a coverage
defect. Under (1)–(4) the corpus is authored truth, so equality — not a band — is the right comparison
(ADR-0012:275: "Equality is right here and only here").

**Strongest alternative, steel-manned.** Harvest the upstream compiler test suites (rust `tests/ui`, 21,406
programs; the JDK's language tests) as the golden corpus: vastly more coverage, written by the language's own
authors, zero authoring cost.

**Why the recommendation wins.** Those suites assert compile/run outcomes, not control-dependence or def-use pairs;
turning them into pair goldens needs the same hand derivation per case, or a producer to generate the pairs — which
reintroduces an observed oracle. They are used instead as the self-consistency corpus of (b) (no crash, no
unresolved jump on legal code, `bound_ratio` reported).

**Trade-off accepted.** An authored corpus is small (the existing tables hold 18 Go and 22 JavaScript cases,
`lower_go_test.go:28-253`, `lower_javascript_test.go:18-264`) and covers constructs, not their combinations at
scale; combination coverage comes only from the corpora of (b).

**The measurement the benchmark task must take.** Per language: count of lowering node kinds and count of kinds with
at least one case (pass: equal); per case, both derivations recorded; native key set equal to the golden set with
nothing outside it (ADR-0012:275).

## (d) Gates per repository class

**Recommendation.** A gate is claimed for a class only when it passes on **at least two instances of that class from
different language families** — one instance is a measurement on one repository, which policy forbids as a
validation; a per-language parity claim (retirement condition 1, ADR-0012:285-288) additionally needs one instance
per language. Classes and the instances these pins supply:

| class | public instances (unit that instantiates it) | private instances | instances ≥ 2 families? |
|---|---|---|---|
| configured typed | kubernetes (Go modules), TS checkout (`go.work`), elasticsearch (Gradle), vscode (93 `tsconfig`), rust (Cargo workspace) | the configured mixed-language repository | yes |
| typed, configuration requires a build step | llvm-project: CMake only; no tracked `compile_commands.json` outside test inputs | — | **no** (one family: C/C++) |
| unconfigured (whole repository) | none | the unconfigured JavaScript-majority repository | **no** — sub-trees only: TS checkout `tsc/testdata/tests/cases` (TypeScript), rust `tests/ui` (Rust) |
| dynamic-language | home-assistant core (Python), TS checkout JavaScript | the configured mixed-language repository is Python-majority (`10-engine-empirical.md:119`); the unconfigured one is JavaScript-majority | yes |
| vendored | kubernetes `vendor/` (4,406 Go files / 48.7 MB), llvm `third-party/` (11.5 MB) | the unconfigured JavaScript-majority repository (committed dependencies) | yes |
| generated | kubernetes (3,786 header-marked Go files / 38.1 MB outside `vendor/`), elasticsearch (1,151 Java under `generated/`), llvm (2,519 C/C++, 115.6 MB with `generated` in the path), TS checkout baselines (29.1 MB JS/TS) | — | yes |
| polyglot monorepo | llvm (C/C++ + 3,119 Python), vscode (TS + 88 Rust + TSX), rust (Rust + 166 JS + 131 C) | the configured mixed-language repository | yes |

| family | gate | notes per class |
|---|---|---|
| `control_depends_on` | per oracle unit (Rust: authored goldens, equality), the native/engine difference is within the A/B band, with every surplus attributed to the two named design causes (exit augmentation on unreachable-from-exit regions; the engine's missing entry dependences and truncated frontier walk, ADR-0012:175) and every shortfall zero beyond the band | vendored and generated units are in scope (the honest denominator counts vendored source as in-repo, ADR-0012:412-414); generated files are where the engine's definition cap bites (`10-engine-empirical.md:122`), so native surplus there is a named cause, never a failure |
| `data_flows_to` | the same band, **signed and per cause** (ADR-0012:321-327): φ-depth, the engine's name-based over-kill, the use-filter substring over-connection | an over-connection never offsets a miss |
| `reads` / `writes` | per-family band per oracle unit; divergence attributed to resolution (ADR-0012:325) | Rust: authored `rw` goldens, equality |
| `calls` | the engine's in-repo-resolved subset within the band (ADR-0012:279,285-288), **and** retirement condition 3: ≥ 95% of in-repo-targeted sites on a configured typed repository, ≥ 85% on an unconfigured or dynamic-language one, by the seeded stratified sample method (ADR-0012:290-304) | Java: authored corpus and capability gain, no band; the ambiguous population does not grow |

**Where a gate cannot yet be claimed.** *Unconfigured* has one whole-repository instance, private; the 85% target
for it is therefore evidence from one repository until a second unconfigured public repository is pinned (the
TypeScript and Rust test-case sub-trees exercise the dependence families, but they are fixtures without in-repo
call targets, so they cannot carry the `calls` target). *Typed, build-step configured* has one family (C/C++); a
second instance from another family is required before its `calls` gate is claimed. Both are recorded here as
under-instantiated, not waived.

**Strongest alternative, steel-manned.** Gate per repository, one threshold each: simpler to read, and each
repository is a real user shape; a class can hide a repository that regresses under a passing class average.

**Why the recommendation wins.** A per-repository gate is a constant validated on one repository, which the owner
forbids, and a count cannot be met on a second repository at all (ADR-0012:299-305, the withdrawn absolute floor).
The class gate is still evaluated on **every** instance — each instance must pass, not the average — so no
repository can hide under its class.

**Trade-off accepted.** Two classes stay unclaimable until more public corpora are pinned, and the minimum of two
instances doubles benchmark cost per class.

**The measurement the benchmark task must take.** For every (class, family, instance): the band, the signed
per-cause native difference and the pass/fail per unit; for `calls`, the sampled in-repo-targeted share with its
bootstrap interval per instance. A class passes a family only when every instance passes and at least two
instances from different language families exist.
